# Scenario mock tool

Standalone reconciliation sandbox at **http://localhost:3081**. It has its own package, server, mock fixtures, tests, and Docker Compose project. ATSPM, a database, camera, credentials, and feature flags are not required.

Choose **Lanes** or **Approaches**, select a scenario, and compare. Additions, deletion, ignore, and reset affect only local mock state. The ten lane scenarios use fictional editable counts. The 43 approach scenarios replay fixed responses generated by the real backend reconciliation rules; comparing again replays that response rather than querying a service.

## Run

From this directory:

```powershell
npm ci
npm run dev
```

For a production build, run `npm run build` followed by `npm start`. For Docker Desktop:

```powershell
docker compose up -d --build
```

The container runs independently of the `atspm` Compose project and binds only localhost port 3081.

## Shared code

The project imports reconciliation rules and report components from `../Atspm/WebUI/src` using the `@/` alias. It shares implementation, not a running app or location state. Keep it in this repository so changes to production behavior are exercised here rather than diverging in copied components. The WebUI no longer contains the `/dev/reconcile-scenarios` route.

## Tests

```powershell
npm test
npm run test:e2e
```

Playwright starts the tool automatically unless it is already running. Install Chromium once with `npx playwright install chromium`. Add `-- --ui` for interactive browser tests. The browser tests reject writes and cover every approach fixture. Regular-location-page API-mocked tests remain in `Atspm/WebUI/e2e` and import the lane fixtures from this project.

`Atspm/ConfigApiTests/ApproachScenarioFixtureTests.cs` verifies each stored approach response against `SignalTemplateService`. When backend rules intentionally change, set `REGENERATE_APPROACH_SCENARIOS=1`, run that test, review the fixture diff, unset the variable, and rerun to validate. Ordinary test runs do not rewrite fixtures. The existing ConfigApiTests pedestrian aggregation compilation errors must be resolved or that unrelated file excluded to run the backend suite.

The regular pedestrian-add UI gap is explicitly represented by a scenario. No scenario claims to validate actual intersection configuration or field detection accuracy.

To test detector properties: select **Approaches → Unconfigured detector channel**, compare, select **119**, and choose **Add selected to… → Mock approach 1**. The shared detector editor opens a draft; edit cells with Enter or double-click, then select **Add detectors**. **Cancel** discards the draft. Expand **Current detector properties** to inspect the values applied to the mock configuration. Comments require a saved detector and are unavailable for drafts.


Phase and overlap additions also open the shared approach editor before applying. Use **Approaches → Same number, separate phase and overlap**, compare, select a phase or overlap, and click **Add Selected**. Edit the draft, then **Add approaches**, or cancel. **Current approach properties** shows the resulting mock values.


Assignment removal scenarios cover protected, permissive, and pedestrian assignments, bulk removal, blocking removal of the last vehicle assignment, and separately confirmed whole-approach deletion. Use the removal button beside an assignment, or select valid assignments and use Remove selected. A retained approach must have a protected or permissive vehicle phase/overlap; a pedestrian assignment alone is insufficient. Removing a protected assignment sets its number to zero. Delete entire approach is a separate optional action that also removes its detectors.
